# Changelog

## Unreleased
- Admin approval of new sign-ups (`REQUIRE_ADMIN_APPROVAL`, on in production): verified users wait in the Admin tab's *Sign-up requests* until approved or rejected; admins are emailed, approved users are emailed; unapproved accounts get no session from any path. New migration `0003` marks all existing users approved.
- Database migrations now use Alembic (`backend/app/migrations`). A baseline revision adopts the existing database in place; `core/migrations.ensure_columns` is gone. Tests fail if models and revisions drift apart.
- Two-factor sign-in (authenticator app + recovery codes), optional for users and required for admins in production. Seeds are encrypted at rest, codes cannot be replayed, a password reset cannot bypass it, and admins can reset a user's 2FA (audited) or use `python -m app.cli.reset_2fa`. `/api/auth/login` can now answer `mfa_required`; `/api/auth/me` includes `twoFactor`.
- Security phase 4: screenshots are decoded and re-encoded to WebP on the server (metadata and hidden data removed, pixel and size limits, per-account storage cap, upload rate limit, streamed size check); every request body is size-limited while it streams; notes, lessons and rule lists have length limits; the calendar download is https-only and size-capped; admin actions are written to an audit log (`GET /api/admin/audit`) and admin routes are rate limited; admin-created users choose their own password from a link instead of receiving one by email; "Download my data" export; security events are logged; optional Sentry; Dependabot and a weekly security-audit workflow. Dependencies upgraded to fix published advisories (FastAPI/Starlette, PyJWT, python-dotenv, Pillow, pytest).
- Security phase 3: logins are now sessions. Access tokens last 15 minutes and live only in the page's memory; a rotating refresh token sits in an HttpOnly cookie (hashed in the new `auth_sessions` table, reuse detection, 90-day cap). Logout, "Log out of all devices", password reset and disabling a user end sessions immediately. `localStorage` holds no token any more. New: `/api/auth/refresh`, `/logout`, `/logout-all`. Everyone is signed out once on deploy. Browser e2e scripts updated.
- Security phase 2: in-memory rate limits on login, sign-up, forgot-password, resend-verification, verify/reset and delete-account (including a 15-minute lockout after 5 wrong passwords per email and a cap of 3 emails per address per hour); passwords must be at least 10 characters, not common, not built from the email, and not found in known breaches (Have I Been Pwned range check, fails open); optional Cloudflare Turnstile human check on sign-up and forgot-password (`TURNSTILE_SECRET`, `VITE_TURNSTILE_SITE_KEY`); email verification is mandatory in production; login takes the same time for unknown emails. Existing accounts with shorter passwords can still log in.
- Security phase 1: in production (`ENVIRONMENT=production`, or on Render) the API refuses to start with the default or a short `SECRET_KEY`, wildcard/localhost/non-https CORS origins, or SQLite; it also sends security headers (HSTS, CSP, nosniff, frame, referrer, permissions), hides `/docs`, marks `/api/auth/*` as `no-store`, restricts CORS methods and headers, and supports an optional `TRUSTED_HOSTS` allow-list. The web app gets a CSP and the same headers (`vercel.json`, `nginx.conf`). Added a gitleaks secret-scan workflow.
- Reorganized the repository into a production layout (backend packages, frontend pages/components/styles, deploy, scripts, docs). No behaviour changes.
- Added Dockerfiles and docker-compose.yml.
- Split dev-only Python dependencies into backend/requirements-dev.txt.
